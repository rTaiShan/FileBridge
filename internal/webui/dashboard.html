Using FileBridge

Applications send requests to this local bridge. FileBridge carries them through the shared folder to a server, which forwards them to an explicitly registered service.

Start a client

Run one client on each computer that needs access to registered services.

filebridge client --share <shared-folder> --client-id <client-id> --servers <trusted-server-id>

The local listener defaults to 127.0.0.1:9000. Omit --client-id to generate and persist one automatically. Omit --servers only when unrestricted server discovery is intended.

Start a server

Run a server on a computer that can reach the registered HTTP services.

filebridge server --share <shared-folder> --server-id <server-id> --config <services.yaml>

The server publishes its service registry and heartbeat to the shared folder. Registered targets must be local to the server.

Call a service

Use an explicit route when selecting a server:

/_bridge/proxy/<server-id>/<service>/<remote-path>

The shorter /<service>/<remote-path> route works only when exactly one discovered server exposes that service. The Services tab always provides the unambiguous explicit URL.
